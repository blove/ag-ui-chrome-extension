# Run simulator (§14.4) — design and plans

**Date:** 2026-09-30
**Requirements:** [`docs/spec/ag-ui-devtools-v0.1.md`](../../spec/ag-ui-devtools-v0.1.md) §14.4 — *"Inject a synthetic interrupt, subagent handoff, or malformed event into the running app to exercise approval UI without a model call. Also needs the hook. This crosses from observation into mutation — gate it behind an explicit 'developer mode' toggle, and never allow it on an origin the user hasn't enabled."*
**Builds on:** §14.3's hook (cacheplane/threadplane#1203) and the Signals capture path.
**Decided with the user:** the simulator **scripts the next run** (not live injection); **two locks** (Threadplane development build + per-origin Developer mode in the panel).

## Decisions

| # | Decision | Why |
|---|---|---|
| **R1** | **Arm, then serve.** The hook listens for `threadplane:devtools:arm` with `{ v: 1, armId, adapter, runs }`; `runs` is an ordered list of scripts — LangGraph: `{ frames: { event: string; data: unknown }[] }`; AG-UI: `{ events: { type: string; [k: string]: unknown }[] }`. The next stream call of an agent of that adapter on the page takes `runs[0]` **instead of the network**; the next takes `runs[1]` (e.g. the resume after an interrupt); and so on. | The whole human-in-the-loop flow runs — the approval UI, the resume — with no model call and no backend state to corrupt. |
| **R2** | **Real code paths.** LangGraph frames go through Threadplane's real `normalizeSdkEvent` and are yielded by a scripted stream in place of the transport's; AG-UI events go through the same `onEvent` handling as a real run (the hook substitutes the source observable for that run). The app's own code is what's exercised. | A simulator that bypassed the adapter would test nothing. |
| **R3** | **One-shot and bounded.** Each run is consumed once; an arm expires after 10 minutes or on `threadplane:devtools:disarm { v: 1, armId }`; a new arm replaces an unconsumed one. Limits: ≤ 8 runs, ≤ 5,000 frames/events per run, ≤ 2 MB serialized per arm; invalid arms are ignored and acknowledged as `rejected` with a short reason. | No lingering state; nothing unbounded crosses into the app. |
| **R4** | **Acknowledgements.** The hook dispatches `threadplane:devtools:ack` `{ v: 1, armId, state: 'armed' \| 'consumed' \| 'expired' \| 'disarmed' \| 'rejected', run?: number, reason?: string }`. The extension captures them like Signals reports (validated, relayed field by field). | The panel shows what actually happened. |
| **R5** | **Lock 1 — Threadplane development build.** The arm/disarm listeners exist only where §14.3's emitter exists (same `ngDevMode && isDevMode()` gate, same opt-out flag); a production bundle contains none of these event names (extend #1203's bundle check). | The page side never offers this in production. |
| **R6** | **Lock 2 — Developer mode, per origin.** A switch in the panel, available only for granted origins, off by default, stored in `chrome.storage.local` keyed by origin. While on, a banner shows: *"Developer mode: this page's next agent run can be scripted from the panel."* The **relay** (ISOLATED world, knows its own `location.origin`) checks the flag before forwarding an arm command to the MAIN world; the panel also disables arming when it's off. | The check sits where the origin is known for certain. |
| **R7** | **Channel.** Panel → service worker (`simulate.arm` / `simulate.disarm` panel commands, tab-scoped) → relay of that tab's **top frame** → MAIN-world inject script (a new message from ISOLATED to MAIN, source-tagged and validated) → `window.dispatchEvent(new CustomEvent('threadplane:devtools:arm', …))`. Acks return like Signals reports. | Reuses the trusted pipeline; the top frame only in v1 (an agent in an iframe is out of scope — stated in the UI). |
| **R8** | **Honest limit.** Lock 2 is enforced by the extension. Any script already on a development page can dispatch `threadplane:devtools:arm` itself; the hook cannot know the sender. This is no more than page code can already do to its own app, and never applies to production builds. Two locks guard against **accidental** scripting, not against code already in the page. PRIVACY.md and the UI help text say so. | — |
| **R9** | **Simulate tab.** Templates per adapter, editable as JSON before arming: *Interrupt (approval)* — run 1 ends at an interrupt with a question, run 2 completes on resume; *Subagent handoff* — namespaced `tools:` / subgraph events and Threadplane's `threadplane.subagent_binding` custom event (read its shape in Threadplane); *Malformed event* — a payload of the wrong shape; *Replay a captured run* — the frames/events of a run from the current capture (LangGraph frames as captured; AG-UI events as captured). An arm list shows each arm's state from acks, with Cancel. | Covers §14.4's three cases plus the most useful one. |

## Part A — extension (this repo; PR auto-merged on green)

- **A1 Contract:** `core/simulate/commands.ts` — `ArmCommand`, `DisarmCommand`, `Ack` types and strict validators (limits R3), templates (R9) as pure functions producing `ArmCommand.runs` (templates from a capture take `JsonlLine[]`/records + a run id). Tests: validation, limits, each template's shape (LangGraph templates must pass the extension's own expander as a sanity check: interrupt template → outcome `interrupted` for run 1).
- **A2 Developer mode + channel:** per-origin flag in `chrome.storage.local`; panel UI switch (Session or the Simulate tab) + banner; panel → sw commands → relay (checks flag for its origin, top frame only) → MAIN message (new ISOLATED→MAIN arm, source-tagged, validated in MAIN) → CustomEvent dispatch; acks captured by the inject listener → relay → sw (per-tab list, cleared with the buffer) → panel. Tests at each layer incl. hostile inputs and "flag off ⇒ nothing dispatched"; e2e with a harness page whose fake hook records arms and emits acks.
- **A3 Simulate tab:** template picker per adapter (adapter inferred from the tab's connections/Signals reports, overridable), JSON editor (textarea with validation errors inline), Arm / Cancel, arm list with states; disabled with a plain reason when Developer mode is off or the origin isn't granted. Visual gate: tab drawn, banner shown when on, an arm reaching the fake hook and its `consumed` ack shown.
- **A4 Docs, gates, PR:** README, PRIVACY.md (R8 in plain words), listing copy (one line, `verify:listing`), spec §14.4 note; mutations (relay skips the flag check → e2e fails; validator accepts 9 runs → test fails); all gates; push, PR, auto-merge.

## Part B — Threadplane (stacked on `feat/devtools-hook`; separate PR; user-reviewed, not auto-merged)

- **B1 Arm store** in `libs/chat/src/lib/devtools/`: listeners for arm/disarm (dev-gated), validation (R3), one pending arm per adapter, expiry, acks. Tests.
- **B2 LangGraph:** before the bridge starts a stream (`runStream`, and the queue-drain and join paths if they start runs), take the next armed run: a scripted async iterable of `normalizeSdkEvent(frame.event, frame.data)` replaces `transport.stream(...)`; ack `consumed`. Tests with an interrupt template: run 1 pauses with `interrupt()` set, `submit({ resume })` consumes run 2 and completes; no network call is made (the test's transport records zero streams).
- **B3 AG-UI:** in `toAgent`'s run start, take the next armed run: an Observable of the scripted events replaces `source.run(input)`; ack `consumed`. Tests: interrupt via the AG-UI interrupt mechanism Threadplane supports (read reducer: `RUN_FINISHED` outcome interrupt / `CUSTOM on_interrupt`), resume completes; no network.
- **B4 Bundle check, docs, PR:** extend #1203's bundle check for `threadplane:devtools:arm`/`disarm`/`ack`; README sections; PR stacked on #1203 (base `feat/devtools-hook`), not auto-merged.
- **Acceptance (extension side, after both):** extend `pnpm --filter ag-ui-harness acceptance:threadplane` to arm an interrupt scenario against the real Threadplane build and assert the acks and the resulting Signals reports.
