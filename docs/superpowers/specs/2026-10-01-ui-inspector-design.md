# UI inspector (§14.5) — design and plans

**Date:** 2026-10-01
**Requirements:** [`docs/spec/ag-ui-devtools-v0.1.md`](../../spec/ag-ui-devtools-v0.1.md) §14.5 — *"For `@threadplane/render` / A2UI: spec JSON ↔ rendered component mapping, with warnings for spec nodes that have no match in the app's registry. Also applies to CopilotKit's A2UI middleware."*
**Decided with the user:** wire extraction for both frameworks **and** a Threadplane hook `render` report (third stacked PR).

## What the wire carries (verified)

- **Threadplane** (Threadplane 0.2.0; A2UI wire v0.9, catalog id `https://a2ui.org/specification/v0_9/catalogs/basic/catalog.json`): A2UI as assistant text starting with the sentinel `---a2ui_JSON---` followed by JSONL envelopes (`createSurface` / `updateComponents` / `updateDataModel` / `deleteSurface`); live as `a2ui-partial` custom events (`{tool_call_id, args_so_far}` — partial tool-call args in 4 tolerated shapes, `libs/chat/src/lib/a2ui/envelope-normalizer.ts`); as GenUI tool calls (`generate_a2ui_schema`, `generate_json_render_spec`, `render_spec`, `render_a2ui_surface`). json-render specs `{root, elements: {key: {type, props, children}}}` as assistant text starting with `{` or `render_spec` args. Transports: AG-UI (`TEXT_MESSAGE_CONTENT`, `CUSTOM`, `TOOL_CALL_*`) and LangGraph (`messages`, `values`, `custom`, `tool_calls`).
- **CopilotKit A2UI middleware** (`@ag-ui/a2ui-middleware` v0.0.2 and v0.0.10): `ACTIVITY_SNAPSHOT`/`ACTIVITY_DELTA` with `activityType: 'a2ui-surface'`, content `{operations: […]}` (v0.0.2) or `{a2ui_operations: […]}` (v0.0.10), lifecycle snapshots with `status: building|retrying|failed`; the app's catalog travels in `RunAgentInput.context` (entry described by `A2UI_SCHEMA_CONTEXT_DESCRIPTION`, value `{catalogId, components: {Name: {allOf: [...]}}}`); basic catalog id `https://a2ui.org/specification/v0_9/basic_catalog.json` (differs from Threadplane's).
- **Threadplane's registry is not on the wire.** An unknown component type renders nothing (and its subtree), silently.

## Decisions

| # | Decision |
|---|---|
| **U1** | `core/genui/extract.ts`: pure extraction of **surfaces** from a capture (records + requests + runs): each surface `{ id, framework: 'threadplane' \| 'copilotkit', format: 'a2ui' \| 'json-render', catalogId?, runId?, components: Map<id, {id, type, props, children: string[]}>, root?, sourceSeqs: number[], status? }`, applying envelopes in order (A2UI `updateComponents` merges by id; `deleteSurface` marks deleted; partial tool args parsed tolerantly — last complete parse wins; json-render elements as components). Handles all formats and both transports listed above. |
| **U2** | `core/genui/catalog.ts`: the app's catalog when knowable from the wire — CopilotKit context entry (exact: names + required props from the schema) — else `undefined`. A known built-in table of the A2UI v0.9 basic catalog (18 names, both ids) used only as an **inferred** catalog, labelled so. |
| **U3** | `core/genui/check.ts`: per surface: `unknown_component` (type not in catalog), `missing_required_prop` (exact catalogs only), `unresolved_child`, `orphaned_subtree` (children under an unknown/unresolved parent — they won't render in Threadplane), `no_root`, `duplicate_id`, `catalog_mismatch` (surface `catalogId` vs advertised). Each finding: exact or inferred. |
| **U4** | Hook `render` report (Part B), same CustomEvent `threadplane:devtools`, discriminated by `kind`: `{ v: 1, kind: 'render', surface: string (A2UI surfaceId, or 'spec:' + json-render root key; ≤128), seq: number (per page), registry: string[] (≤500 names, each ≤128), elements: { key: string (≤128); type: string (≤128); state: 'mounted' \| 'fallback' \| 'unresolved' \| 'hidden' }[] (≤2000), tMs: number }`. Emitted when a rendered spec's resolution changes. Names and states only — no props. §14.3 signal reports (no `kind`) are unchanged. |
| **U5** | Extension capture: the existing `threadplane:devtools` listener validates either shape (signals or render), relays field by field; the worker keeps a separate per-tab ring of render reports (500), mirrored, cleared with the buffer; the panel gets them like signals. |
| **U6** | **UI tab:** surfaces per run (framework, format, catalog id, exact/inferred badge), a component tree (root → children), each node badged **rendered / fallback / not rendered / unknown type** — from the latest hook render report for that surface when present, else from U3 — orphaned subtrees flagged; selecting a node shows its props (captured content; it follows the panel's existing data handling, and nothing new is exported) and links its source frame in Timeline; findings listed per surface. Empty state without fault words. |
| **U7** | Not exported in v1 beyond what's already in the capture (render reports are live-only, like signals). |

## Part A — extension (PR here, merge on green)
- **A1** extraction (U1) + catalog (U2) + checks (U3), with golden fixtures: convert a slice of Threadplane's `examples/chat/angular/public/stage-replay.json` (LangGraph SSE with A2UI) into `.agui.jsonl` via the existing `langGraphJsonl` helper (a small committed fixture, provenance in the test), and AG-UI sequences from `@ag-ui/a2ui-middleware` tests (`/Users/blove/repos/ag-ui/middlewares/a2ui-middleware/__tests__/` and the v0.0.10 worktree) hand-built into captures incl. a CopilotKit `RunAgentInput.context` catalog; json-render from Threadplane's cockpit fixture shapes.
- **A2** render report contract + capture (U4, U5): validator for the `render` shape beside the signals one; listener/relay/worker/panel; e2e with a harness page dispatching render reports.
- **A3** UI tab (U6) + visual gate (fixtures + a seeded render report) + docs (README, PRIVACY.md one sentence: names and states only), mutations, gates, PR.

## Part B — Threadplane (stacked on `feat/devtools-scripted-runs` / #1204; separate PR; user-reviewed)
- **B1** in `libs/chat/src/lib/devtools/`: a `render` report emitter (dev-gated like the signals emitter; bounds per U4).
- **B2** in `libs/render` (`render-spec.component.ts` / `render-element.component.ts`): compute per element `state` from the existing `entry()` / `mountClass()` / `visible` logic (unresolved = no registry entry; fallback = entry fallback while props not ready; hidden = not visible, incl. under an unresolved parent; mounted otherwise), registry names via `registry.names()`, surface id (A2UI surfaceId from the surface component, `spec:`+root for json-render), debounced per surface; emit only on change. Never read prop values.
- **B3** tests (both formats; unknown type → `unresolved` with its children `hidden`; fallback; registry names), bundle check extended (no `kind:'render'` emitter in production), README, PR (base `feat/devtools-scripted-runs`), not auto-merged.
- **Acceptance** (extension side, after both): extend `acceptance:threadplane` to render an A2UI surface with one unknown component in the real Threadplane build and assert the extension's UI tab data shows it `unresolved` with its subtree `hidden`.
