### 2.2 Description — replace the whole field

Plain text; the store does not render Markdown. 3,890 characters (limit 16,000).

```
Debug agent streams on the wire, not in your app

AG-UI is an event protocol over server-sent events, and LangGraph Platform streams its runs the same way. When an agent run misbehaves, the Network panel shows you an opaque text/event-stream and console.log shows you what your app thinks happened. AG-UI DevTools shows you the wire: every event in order, grouped into runs, with the protocol violations named and located.

Why the existing options do not work

• Chrome's Network panel gives you raw data: lines. No decoding, no run grouping, no state reconstruction, no validation.
• In-app inspectors ship inside your bundle, are tied to one framework, and cannot help an Angular, Vue, or vanilla AG-UI app at all.
• Editor extensions need a runtime in dev mode, so they go dark exactly where bugs are hardest to reproduce.

This is a wire-level tool. It attaches to the protocol instead of the framework.

What it does

• Captures agent streams from fetch, XMLHttpRequest, and EventSource
• Decodes SSE framing and groups events into runs and threads
• Reads LangGraph Platform runs too — every frame keeps its LangGraph event name, subgraphs fold into child runs, and the panel shows the AG-UI events each frame implies, so one timeline covers both
• Validates protocol invariants and names each violation at the event that caused it
• Reconstructs messages, tool-call trees, and state with full RFC 6902 patch history
• Measures time to first token, run duration, and streaming stalls — in the run table and on the timeline
• Inspects generative UI — A2UI and json-render surfaces as component trees, flagging types the app's catalog lacks
• Records and replays — export a capture as .agui.jsonl and reopen it anywhere
• Turns a run into a test — any capture exports as a TypeScript fixture module, and a LangGraph run as a ready-to-run Threadplane spec that replays it through @threadplane/langgraph's MockAgentTransport
• Names the CopilotKit runtime and the agents it reports, read from the /info response the page already fetches
• Flags an enabled tab in the toolbar once it speaks AG-UI or LangGraph Platform

Privacy, stated as fact

This tool sits where prompts and completions flow, so its posture is not a matter of trust:

• No network egress. Ever. No remote host permissions, no fetch from the service worker or the panel, no telemetry, no update pings, no crash reporting.
• Opt in per origin. The extension ships inert. Only localhost, 127.0.0.1, and 0.0.0.0 are registered up front; every other origin takes an explicit click.
• Nothing on disk by default. Capture lives in memory with a chrome.storage.session mirror that Chrome clears when the browser closes.
• Headers are never captured except content-type. Authorization headers and cookies are never read, never stored, never exported.
• Redaction on export for bug-report bundles: text, reasoning, tool arguments, tool results and state values are replaced in the events that carry them — field by field on a LangGraph capture; see the privacy policy for the exceptions — while structure, types, ordering, sizes and timings survive, which is what a protocol bug report actually needs.
• One switch changes what a page does, and it is off. Developer mode is per origin, off by default, and offered only where capture is enabled. With it on, the panel can hand an app built to accept one — a Threadplane development build, 0.3.0 or later — a script for its next agent run: events the app plays through its own code. It is data, never code the extension runs, and on any other app it does nothing.

Every claim above is checkable by reading the built manifest.json, and the repository's build verification asserts them on every commit.

Open source

MIT licensed. Source, issues, and the full specification: https://github.com/blove/ag-ui-chrome-extension
```

## 3. Privacy practices tab

### 3.1 Single purpose description

```
Capture and inspect AI agent event streams (the AG-UI protocol and LangGraph Platform) on pages the user explicitly enables, for debugging.
```

### 3.2 Permission justifications

**storage**
```
chrome.storage.local holds one thing - the per-origin Developer mode switch, off by default, removed when the user turns it off or revokes the origin. chrome.storage.session mirrors each inspected tab's captured events and detection state so they survive the service worker being suspended; Chrome clears it when the browser closes. Nothing is synced and nothing is written to disk unless the user exports a capture themselves. The per-origin capture opt-in is Chrome's own optional host permission grant, not a stored value.
```

**scripting**
```
Registers the capture content scripts at runtime on origins the user has explicitly granted, via chrome.scripting.registerContentScripts. This is required precisely because the extension ships with no static remote host permissions - without it, capture could only ever work on localhost.
```

**Host permission justification** (for `optional_host_permissions`: `http://*/*`, `https://*/*`)
```
Requested one origin at a time, only when the user clicks to enable capture on that page. It is needed to read the server-sent-event response bodies the page is already receiving. No origin is granted at install time.
```

`action` needs no justification — it is a manifest key, not a permission.

### 3.3 Are you using remote code?

**No, I am not using remote code.** If the dashboard asks for a justification anyway:

```
No. Every script the extension runs ships in the package; it loads nothing from a CDN or any server, and has no fetch, XHR or WebSocket of its own. The panel calls chrome.devtools.inspectedWindow.eval with two constant expressions bundled in the package (reading location.origin, and the page's ng-version attribute). Developer mode, off by default per origin, sends the inspected page a script of agent-protocol events as JSON data in a DOM CustomEvent, for a Threadplane development build to play through its own code; the extension never evaluates it.
```

Verified on the 0.2.0 build: no `new Function`, no `importScripts`, no remote `import()`, and the
only URLs in the shipped JavaScript are XML namespaces and two A2UI catalog **identifiers**
(`https://a2ui.org/…catalog.json`), which are compared as strings and never fetched.

### 3.4 Data usage

0.2.0 handles no new kind of user data. LangGraph Platform streams are the same kind of content
as AG-UI streams; the Developer mode flag is a setting; the Threadplane hook reports (Signals,
render report) carry names and states only, are shown in the panel and are never exported. So:

- [ ] **Keep the data-type answers you gave for 0.1.0.** The extension transmits nothing off the
      device; everything it reads is processed locally in the user's own DevTools. If 0.1.0
      declared nothing and you want the conservative reading of "collect", tick **Website
      content** (it reads the page's agent-stream responses) — and nothing else.
- [ ] Tick all three certifications: not sold to third parties; not used or transferred for
      purposes unrelated to the item's single purpose; not used or transferred to determine
      creditworthiness or for lending.
- [ ] Privacy policy URL: `https://github.com/blove/ag-ui-chrome-extension/blob/main/PRIVACY.md`

## 4. Test instructions (reviewer notes)

Paste into the **Test instructions** tab if the dashboard offers one; otherwise into any
"notes for the reviewer" field the submission flow shows.

```
AG-UI DevTools is a Chrome DevTools panel for debugging AI-agent event streams (the AG-UI protocol and LangGraph Platform). It needs no account, no login and no backend.

QUICKEST CHECK - works on any page, needs no agent app:
1. Download a demo capture: https://github.com/blove/ag-ui-chrome-extension/raw/v0.2.0/packages/devtools/listing/fixtures/demo.agui.jsonl (also demo-langgraph.agui.jsonl and demo-genui.agui.jsonl in the same folder).
2. Open any web page, open DevTools (F12), and choose the "AG-UI" panel (behind the >> overflow if the tab strip is full).
3. Click Import and choose the file. The Timeline fills with two runs; the toolbar shows "1 issue" - click the red row near the end to see the protocol violation. Runs, State, Messages, UI and Session show the same capture from other angles. The demo-genui file shows the UI tab's component tree; demo-langgraph shows a LangGraph Platform stream and, under Session > Export, an enabled "Download Threadplane test" button.
Importing reads a local file only; nothing is uploaded.

LIVE CAPTURE:
- On http://localhost, 127.0.0.1 or 0.0.0.0, capture is on by default (the content scripts are registered for those origins in the manifest). Any app that streams AG-UI or LangGraph Platform events over server-sent events appears in the panel live.
- On any other origin the panel shows "Enable capture for <origin>". Clicking it requests that one origin through chrome.permissions (optional_host_permissions) and registers the content scripts for it with chrome.scripting.registerContentScripts; the panel then offers to reload the page, which capture needs. Nothing is captured on an origin the user has not enabled.
- The toolbar icon shows a badge (AG, LG or A+L) on a tab whose page has spoken AG-UI or LangGraph Platform, on enabled origins only. The icon has no popup.

DEVELOPER MODE (new in 0.2.0; off by default):
- The Simulate tab (and Session > Run simulator) has a "Developer mode for <origin>" switch, offered only on an origin where capture is enabled, stored per origin in chrome.storage.local, and shown by a banner on every panel tab while on.
- With it on, the Simulate tab can "Arm" a script for the page's NEXT agent run - e.g. an interrupt awaiting approval, a subagent handoff, or a malformed event - so an app's approval UI can be exercised without calling a model. The script is JSON data, delivered to the page's top frame as a DOM CustomEvent; the extension never executes it. It only has an effect on an app built to listen for it: a Threadplane development build, version 0.3.0 or later (not yet published at submission time). On any other page the arm is reported as unanswered and nothing changes.
- The switch is checked by the extension's isolated content script against the page's own origin before anything is dispatched.

PRIVACY: the extension makes no network requests of its own, has no static host permissions, captures no headers except content-type, and keeps captures in memory and chrome.storage.session only. Export (to a file the user chooses) is the only way data leaves the panel. Policy: https://github.com/blove/ag-ui-chrome-extension/blob/main/PRIVACY.md. Source (MIT): https://github.com/blove/ag-ui-chrome-extension
```

## 7. GitHub release notes — v0.2.0 (draft)

Paste over the generated notes on the `v0.2.0` release.

```markdown
## AG-UI DevTools 0.2.0

The panel now reads **LangGraph Platform** as well as AG-UI, turns a captured LangGraph run into a
**Threadplane test** in one click, and adds a **generative-UI inspector** and a **toolbar badge**.
No new permissions.

### New
- **LangGraph Platform streams** (`/threads/{id}/runs/stream`) fold into the same runs, messages,
  tool calls and state as AG-UI. Every frame keeps its LangGraph event name, subgraphs become
  child runs, a join stream continues its run, and the detail pane lists the AG-UI events each
  frame implies. Session names the protocol. (#43, #44, #45, #48, #50)
- **Threadplane test export** — Export → *Download Threadplane test (.spec.ts)* writes a spec that
  replays the capture through `@threadplane/langgraph`'s `MockAgentTransport` and passes as
  generated. (#52)
- **UI inspector** — the UI tab lists every A2UI / json-render surface in a capture as a component
  tree with rendered / fallback / not-rendered / unknown-type badges and catalog findings (exact
  against a catalog the app advertised, inferred against the A2UI basic catalog). (#60)
- **Toolbar badge** — `AG`, `LG` or `A+L` on a tab whose page spoke AG-UI and/or LangGraph
  Platform, on the origins capture runs on; the tooltip names the stack. (#55)
- **`/info` discovery** — on a CopilotKit runtime, Session names the runtime version, mode and
  agents from the `/info` response the page already fetches. (#41)
- **For Threadplane development builds (needs Threadplane 0.3.0 or later, not yet released):**
  the **Signals** tab shows which agent signals each event wrote (#57), and the **Simulate** tab,
  behind a per-origin **Developer mode** switch that is off by default, scripts the app's next
  agent run — an interrupt, a subagent handoff, a malformed event, or a captured run (#59). The
  UI inspector also uses a dev build's render report for the node states when present.

### Privacy
- **Field-level redaction for LangGraph captures**: each redaction group removes its own content
  in streamed events, graph state and the request body; content no group owns is redacted in full.
  Every AG-UI field is attributed to a group and fails closed. (#46, #47, #49)
- Fixed: a LangGraph request body could carry the user's prompt into a redacted export. (#46)
- `PRIVACY.md` documents Developer mode and states exactly what `chrome.storage` holds.

### Fixes
- Capture silently stopped on every granted (non-localhost) origin after an extension update. (#42)
- A dropped LangGraph connection's close no longer restamps a message its join ended. (#51)
- Import validates every header and line field once, in one place. (#54)
- Download filenames slug `capturedAt` the same way the host does. (#56)

### Permissions
Unchanged: `storage`, `scripting`, and per-origin `optional_host_permissions`. The manifest gains
an `action` key (the toolbar icon and badge; no popup, no permission).

**Full changelog:** https://github.com/blove/ag-ui-chrome-extension/compare/v0.1.0...v0.2.0
```
